## Contract: single authenticated financial command
Proposed RPC bt_purchase_commit_document_v2 (name provisional). Inputs: company/site IDs, document SHA-256, private staging object ID, kind (quotation/estimate/order/credit), supplier, reference, original reference, PO, observed project, source filename, parser version, independently extracted subtotal and line count, rows, explicit revision choice, alias confirmation and expected budget revision version. Use a server-issued verification receipt bound to actor, tenant, site, file digest, normalized payload and expiry. Do not trust client plan status, totals, IDs or verification flags as authorization. Existing admin and active site checks, RLS and tenant constraints must remain.

Upload PDF first into private tenant/site staging with RLS, immutable random path, validated bytes/size/digest. A trusted verifier must read the original and bind extraction evidence to the receipt; no external AI/OCR transfers without approval. PostgreSQL cannot atomically write object storage bytes, so use staged immutable objects, then a single database transaction registers the document metadata and all financial rows. Cleanup only unreferenced staged objects after retention window; never remove committed originals. Retry after ambiguous network failure returns existing committed receipt for identical payload, not a second financial write.

Transaction:
1. Authenticate actor and authorize admin membership, active site and staging object ownership; validate receipt and scope.
2. Lock site/budget revision, recheck duplicate hash/reference within tenant, distinguish identical retry from conflicting reference (manual review). Never use PO as identity. Revalidate signs, non-null finite decimal values, units, item coverage, subtotal, currency CAD and line arithmetic in SQL numeric; refuse partial extraction and ambiguous credits. Validate alias scoped to supplier/company, refuse ambiguous destination.
3. For initial quotation insert budget and supplier price document with common source document ID; for replacement preserve active extensions, version the base; extension appends rows and prices. Estimate never invents supplier. Price-only action optional explicit scope and semantics; currently not implemented. Order/credit adds signed rows via existing verified production mechanism, not by editing history. Invoice/delivery never create commitments.
4. Store original PDF metadata, document identity, provenance, actor and timestamp; save confirmed alias; register receipt. Any error rolls back all DB rows. Return documentId, status imported/duplicate, authoritative total, revision version. No success UI before commit.
5. Recompute monitoring from authoritative active rows. Compare prices on historical orders and draft imports. Separate unmatched products, ambiguous prices, unpriced and no-reference coverage from genuinely compliant lines. Credits reduce committed totals but are not positive price alerts.
